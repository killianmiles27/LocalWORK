# Setup

## What you need

- Windows 10 or 11, 64-bit, with Microsoft Edge WebView2. The installer can fetch WebView2 if it is missing; that step needs internet access.
- A model: a [Strata installation](https://github.com/Niko1221/Strata) (recommended; the first-run wizard can walk you through it), or [PolyStrata](https://github.com/VecSzn/PolyStrata) for models beyond Qwen, or any OpenAI-compatible server on this PC, such as LM Studio or Ollama. You also need enough GPU memory, system memory and disk space for that model. Follow Strata's current hardware requirements rather than treating one developer's PC as a minimum specification.
- Internet access for initial downloads. After setup, local inference and file work can run without a hosted AI service. Web tools still need the network.

Model downloads can be large. LocalWORK does not include weights. Its model library suggests models using reported memory and disk capacity; these estimates are not benchmarks or a guarantee that a model fits.

## Guided PolyStrata setup

Choose **No, help me set one up** in the wizard, or open **Settings → Model → Model library**. Install PolyStrata from its latest GitHub release, confirm its runtime dependencies, then choose a suggested model and context size. Each download needs a click. Model setup is delegated to PolyStrata's trusted upstream scripts and may fetch dependencies and large model files. Updates keep the previous engine folder and may need to set models up again; review the download notice first.

You can also add a supported GGUF already on disk, or inspect/download another Hugging Face GGUF using the library. Compatibility depends on the upstream engine; downloading weights does not guarantee support. Existing model JSON configurations can still be selected through Engine and setup. LocalWORK starts and stops the selected managed model; an external server remains under your control.

In **Local models in your picker**, check the profiles you want to see in chat. The picker groups profiles by model rather than listing every configuration as a separate model. Download operations show a progress bar immediately, with size and percentage when available; preparation/extraction use an indeterminate bar.

**Tune for this PC** runs supported upstream calibration and saves its changes. Stop the model first. Calibration runs inference measurements and can take time; it is not a general optimizer for every model family. Unsupported engines return an error rather than claiming a speed improvement. No calibration runs merely from opening the library.

## Install Strata and a model

1. Follow the installation instructions in [Strata's README](https://github.com/Niko1221/Strata#readme). On Windows, its `START-HERE.bat` handles initial setup; `SETUP.bat` can reconfigure an existing installation.
2. Confirm that Strata can answer a short prompt on its own before connecting LocalWORK.
3. Keep the Strata installation folder and the model configuration JSON it uses. The folder must contain `serve\server.py` and `.venv\Scripts\python.exe`. Use a configuration generated by Strata, with an `args` array and model paths that exist on your PC.
4. Close the separately launched model server before starting LocalWORK, to avoid loading another copy into GPU memory.

Treat the model JSON as executable configuration. It can select an engine executable, arguments, and environment variables. Do not import configurations from an untrusted source.

## Build from source

Install Git, PowerShell 7, Python 3.11 or later, Node.js 22.12 or later with npm, stable Rust for `x86_64-pc-windows-msvc`, and Visual Studio Build Tools with Desktop development with C++ and a Windows SDK. See [Tauri's Windows prerequisites](https://v2.tauri.app/start/prerequisites/#windows).

In PowerShell, from a folder where you keep source projects:

```powershell
git clone https://github.com/killianmiles27/LocalWORK.git
Set-Location LocalWORK
npm ci
pwsh -NoProfile -File scripts/fetch-vendor.ps1
pwsh -NoProfile -File scripts/build-agent.ps1
pwsh -NoProfile -File scripts/install-mcp-libs.ps1 -Python 'D:\Tools\Strata\.venv\Scripts\python.exe'
npm run tauri -- build --no-bundle
```

Replace the example Python path with the one in your Strata installation. No particular drive or folder name is required. The vendor script downloads OfficeCLI, portable Node, Playwright, Chromium, whisper.cpp, and a voice model. The agent build uses a pinned source revision and LocalWORK's tracked compaction patch. These commands require internet access and can take several minutes.

The executable is `src-tauri\target\release\localwork.exe`. Running it from the build directory uses the repository's runtime resources. To work on the UI, use `npm run tauri -- dev` after preparing those resources. A plain Cargo build is not a replacement for the Tauri release build.

For a portable folder or installer, preserve the runtime resources; copying only the EXE will not work. `scripts/deploy-local.ps1 -Destination 'D:\Apps\LocalWORK'` updates an **existing** installation and keeps a backup. For installer packaging, signing, and redistribution checks, use [release.md](release.md).

## First launch

The first-run wizard asks whether you already have a model:

- **Yes, Strata or PolyStrata is installed:** choose its folder (the one with `START-HERE.bat`). With PolyStrata, every `strata-<model>.json` in that folder shows up in the model menu under *Models*, and the context window is read from the running server, so compaction follows whichever model is loaded. The model you set up there is picked automatically. LocalWORK starts and stops it for you.
- **Yes, I run my own model server:** Strata, LM Studio, Ollama or any OpenAI-compatible server on this PC. Start it yourself, then press *Test and connect*. With the port left empty, LocalWORK tries the usual ones (8080 for Strata or llama.cpp, 1234 for LM Studio, 11434 for Ollama, 8000 for vLLM, 30000 for SGLang). Set the context size your server uses.
- **No, help me set one up:** the model library installs PolyStrata from GitHub and offers model downloads or existing files. You confirm each download.

Then choose where projects live and whether web tools are on. The model indicator turns ready once the model has loaded, which can take a while the first time.

Cloud use is optional and off by default. See [cloud providers, routing and privacy](CLOUD.md) for setup and limits. Cloud chats still need the configured Python runtime for Workbench tools.

**Make it fast:** once the model runs, ask it to *tune yourself for this PC*. The model-tuning skill reads your hardware and Strata's options, then writes launch profiles (Sprint 16K, 64K, 128K, 256K) that you switch between in the mode menu. On the same PC, tuned settings can take a model from 16K context at 30 tokens/s to 256K at 40+.

**Add extras:** the app ships without plugins. Settings → Plugins → *Get plugins* lists the [official plugins](https://github.com/killianmiles27/LocalWORK-plugins) (CPU/GPU bar, electricity cost per task) with an *Install* button each, and you can add other GitHub plugin repositories there.

**Updates:** Settings → App → *Check for updates* installs a newer signed release. Turn on *Update automatically when LocalWORK opens* to have it check and install at each launch. It is off by default.

Both paths can be changed later in **Settings → Model → Engine and setup**. Stop and start the model after changing them. Existing conversations and files are retained.

For scripted launches, `LOCALWORK_STRATA_ROOT` and `LOCALWORK_MODEL_CONFIG` provide defaults when no paths have been saved. A `strata` folder beside the executable can also be discovered. Saved selections take precedence. Settings live in `%LOCALAPPDATA%\Workbench\settings.json`; normal setup does not require editing that file.

## Troubleshooting

| Problem | Check |
| --- | --- |
| Model never becomes ready | Run Strata separately with the same model configuration. Confirm model files, driver support, available memory, and any paths in the JSON. |
| Missing Python or server | Choose the Strata folder itself, containing `.venv\Scripts\python.exe` and `serve\server.py`. |
| Chat reports missing tools | Check `vendor\aionrs.exe`, the Office/browser resources, and `workbench-mcp\server.py`. Rerun the setup scripts. |
| Web tool import error | Rerun `install-mcp-libs.ps1` with Strata's Python path. Its dependencies are separate from the model's environment. |
| Voice input unavailable | Check `vendor\whisper\whisper-cli.exe` and its model. Rerun the vendor script. |
| Page-count verification times out | Other document checks can still run. Page count remains unverified; inspect it in Word. |
| Browser cannot reach a corporate site | Web fetching bypasses environment proxies and blocks private destinations. Browser requests also have restrictions. Authenticated and restricted-network sites may not work. |
| SmartScreen warns about a build | Updater signatures and Windows Authenticode signatures are different. Do not disable Windows protection globally; verify the source and publisher before running an unsigned build. |

The data folder contains logs, conversations, cached pages, and browser profiles. These can contain private information. Redact them before attaching anything to a public issue.
